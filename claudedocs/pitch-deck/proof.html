증명 오답 한 번이 학생 약점 자산이 된다.

Proof + AskAI = 단일 학습 사이클. 한 번 틀리면 매일 복습큐에 들어옴.

— LEFT · Drill 환류 (Proof → AskAI)

  • i.
    증명 오답 발생
    FillBlank 빈칸 X 또는 Ordering 순서 X → exam_wrong 신호 발화.
  • ii.
    복습 카드 자동 생성
    AskAI의 약점 카드 발행 모듈이 자동 카드화 (단원·항목 기록).
  • iii.
    자동 복습큐로 진입
    학생 일일 복습큐에 자동 편입. "모름" 시 즉시 재진입.
  • iv.
    강사 시각화
    Homeroom 대시보드에 학생별 증명 약점 단원 표시 — 강사 코멘트 ROI ↑.

— RIGHT · 시장 포지셔닝

  • i.
    수능 수학 — 증명형 문항
    고2~고3 시장. 매년 출제. 콴다·매스프레소 모두 증명 단계 평가 X.
  • ii.
    내신 — 학교별 변별 문항
    고1~고2. 학교마다 증명 출제 패턴 다름. 학원별 증명 라이브러리가 moat.
  • iii.
    KMO · 영재고 · 과학고
    상위권 학원 시장. 증명 능력이 진학 결정 요소. 고객 단가 높음.
  • iv.
    왜 경쟁사가 안 하나
    증명 데이터 직접 만들어야 함 (수능 콘텐츠 회사 못 따라옴). 학원이 직접 만든다는 게 이점.

학생이 증명 빈칸을 채우는 실제 화면.

apps/student/src/pages/ProofFillBlankPage — 단계별 사고를 강제하는 UI
f'(x) f(b)−f(a) b−a
1
증명 본문 + 빈칸
평균값 정리 같은 단원의 증명을 단계별로 분해. 핵심 단계만 빈칸 처리.
2
하단 보기 선택 (수식 칩)
함정 보기 포함. 학생이 "왜 이게 답인지" 사고 강제. 단순 객관식 X.
3
즉시 채점 + 단계 해설
제출 즉시 빈칸 단계별 정답 일치 표시. 틀린 단계의 해설 자동 노출.
4
오답 → AskAI Drill 환류
증명 오답 = 시험 오답 신호 발생. 다음 날 자동으로 복습큐에.
5
강사용 ProofEditor
증명 본문 + 빈칸 마킹 → 학원 자체 증명 라이브러리 누적. 다른 학원이 못 따라옴.
